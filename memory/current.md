The project index is empty and the unrelated `flake.lock` diff is byte-identical to its original state. Review and any separately authorized staging/commit are next; no implementation blocker remains.

`llib.modules.discoverValidatorFiles { root; modulesDir; }` returns distinct `{ file; path; }` records for descriptor path prefixes and the modules root, ordered by depth and then path. `llib.flakeParts.mkValidatorApplications` imports each file with only static lib/llib/owner path, rejects unsupported structures/branches and requires boolean predicates. Its `moduleRegistry` function validates metadata and returns the input; `nixosConfigurations registry` wraps each selected system lazily. All applicable constraints compose through conjunction, with file/branch/system error context and preserved specific assertion errors. Flake integration and tests use these same apply functions. Core execution does not deep-force whole configurations/registries or call external module, overlay or functionTo values.

Synthetic tests cover hierarchy/deduplication/order, absent intermediate files and branches, no-validator identity, both branches, false/assertion/non-boolean failures, invalid declarations, typed Registry/per-system apply and independent valid/invalid systems. Actual FP types also test UID-from-Host, Feature recipients, homeDirectory and Noctalia/Waybar defaults alongside deliberately throwing unrelated external values and a deferred Workload function. An initial fixture used `builtins.isFunction` incorrectly for a merged `functionTo`; current Nixpkgs represents that as a callable attribute set, so `lib.isFunction` is required. This was a test correction; no validation-induced recursion was reproduced and no defaults or validation placement needed a workaround.
