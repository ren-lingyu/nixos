# Declaration registration independent of shared behavior

## Purpose and composition

Flake-parts options describe each system before nixosSystem is called. Configuration values and static metadata have separate schema branches, moduleRegistry owns external OS/HM/overlay adaptation, and nixosBuilder supplies the constructor, HM integration and specialArgs. The builder selects enabled implementations in this outer layer, then produces an internal readOnly OS config.modules view by adapting configuration and merging metadata. HM reads that view through osConfig.modules. Peers still check rather than enable dependencies.

The adapter only calls values whose declared type is functionTo and recursively adapts submodules; it does not guess that arbitrary functions/packages should execute. Outer selection is not a same-level NixOS imports/config cycle. An early overflow came from a declaration aggregator selecting itself during import collection. Session-wrapper readOnly defaults conflicted with real definitions, so intermediate options were removed in favor of direct greeter session-package contributions. The source reports two checks at their respective dirty stages, not a pass for every later change.

## Users and interfaces

Directory-named user profiles retain unique bound UID and host-subset constraints. Outer configuration chooses user identities and Feature allowUidList. The builder sends user HM implementation to the bound UID and Feature HM implementations/external homeModules to recipients; other kinds contribute through sharedModules. Per-user interfaces and OS internals remain declaration mechanisms distinct from implementation enablement. Parent disablement prevents implementation/external integration loading; a child switch does not independently activate its parent.

## Host facts and graphics

Host metadata is now loaded independently of enablement. UID slots and monitor facts remain available for all hosts without activating their OS configuration. Data integrity applies even to disabled hosts. Monitor output names are nonempty/unique and at most one has the default role; dimensions and non-null scale/refresh are positive. The global host rule now requires exactly one enabled host; graphical consumers additionally require a default monitor. The available default monitor is selected safely after cardinality checks. This separates hardware facts from consumer requirements. SSH host identity separates material from runtime paths, with age recipients derived from SSH public identity rather than a second independent identity. The shared getter now throws for zero/multiple selected hosts with contextual names. A global exactly-one assertion remains because laziness can avoid calling the getter; tryEval lets the assertion report the invariant. Returning an empty set had produced unrelated missing-field failures before assertions.

## Desktop and native capabilities

Niri remains the main native desktop and starts Noctalia v5 from HM settings. OS Noctalia configuration supplies recommended services without installing its own competing user launch path. Noctalia now owns normal/idle/pre-suspend locking; swaylock remains an allow-when-locked rescue path. One login_box is centered on the default monitor using mode/scale-derived logical dimensions, with weather false and unlock hint true. Custom clock/weather trials were withdrawn; earlier successful migration checks do not verify this final lockscreen stage. Other outputs remain locked; runtime settings may override declarative values.

Greetd's temporary Sway/gtkgreet and the independent IceWM/startx fallback retain separate session duties. Browser reuse across concurrent sessions remains a historical unresolved report. Native xdg.terminal-exec supplies terminal capability; Yazi/Wayfile handle directories and the independent FileChooser portal only affects clients using it. ThinkBook framebuffer initialization is a host-gated oneshot/udev path; kmscon ownership proposals remain unadopted.

## Secrets and agent inputs

The secret feature is renamed sops across namespaces and helper/test references. Per-user SOPS inventory remains optional and supplies the bootstrap key bridge with restricted group access. Agent-first provider interfaces expose enablement and an API-key file path, without assuming its secret manager. The personal user guards SOPS-derived inputs; Agent drops a global SOPS dependency. A nullable model-interface proposal was withdrawn; enabled providers determine default model fields and an explicit enabled-provider list. No final runtime/model request is tested. OS age/agenix-rekey infrastructure is now independent of optional HM/application SOPS, motivated by keeping base secret deployment usable when SOPS tooling builds/downloads block. Host runtime SSH identity and its public key feed rekey setup; master identities are separate inputs. The initial age-recipient hostPubkey wiring has been corrected to SSH public key. Public/ciphertext review does not establish private-key custody or runtime decryptability. The owner requires text-only encrypted files in Git. Dedicated rage-armored is scoped to rekey tooling and adds armor to ordinary encryption without changing decrypt/already-armored calls. It preserves the underlying package, embeds Scheme body with builtins.readFile, adds the Guile shebang and substitutes an exact executable token. Binary age output was an encoding concern, not evidence of encryption failure. The final wrapper has static evidence, without a new build or runtime proof.

## Library and verification

The public library is organized by responsibility: types, modules, hosts, features.sops, packages and flakeParts, with flakeParts.types retained. The collection entry mkNixosConfigurations maps to mkNixosSystem. The former unused UID grouping API/tests are removed; current per-UID accumulation belongs to the builder. Configuration adaptation follows declared types, and module internals/interfaces retain their established scopes. This is not a blanket shrinking of every export. The source establishes targeted review for these later moves, not a new Nix pass.

## Network ownership

Interconnect has been removed. Stable WireGuard membership and encrypted key references belong to hosts; the public host helper purely derives the selected host's networking from the registry. Endpoint hosts define numbered networks, and other participants become spokes. Role checks are per network, so being a hub elsewhere does not suppress needed spoke keepalive/endpoint settings. Addresses and interface names derive from stable host numbers, not directory order. No-WireGuard selection returns an empty result without reading a private-key path. Builder implementation and host wiring were independent useful source states; their source reviews do not prove a deployed handshake. The builder now separates topology from configuration, publishes a readOnly networking.wireguard.topology view and exposes interface derivation for consumers. Endpoint metadata requires a local listen port. Common identity/boot/WireGuard modules consume host facts; MateBook joins the host inventory. Topology is configuration knowledge, not a live peer-health registry.

## Definition ownership

Internal options designate producer ownership, not access security. Direct internal unique values become readOnly base-typed values where exactly one raw definition is intended; overwritten defaults are removed. Nested element uniqueness is retained where meaningful. User UID remains a public final-composition input; produced host UID metadata remains internal. Provider defaults/fallbacks are consumer views rather than extra readOnly definitions. Nix expression formatting choices do not establish build equivalence. Getter tests and global module assertions have distinct roles. A user-reported check of a whole working tree cannot prove a different partially staged snapshot; the source preserves that staging correction.

## Workload responsibilities

A fourth peer category, workloads, discovers service roots and validates their OS/HM availability. Caddy reverse-proxy and WBO whiteboard containers receive explicit address, port, network-interface and permitted-source inputs; they do not automatically enable from host identity or refer to the removed interconnect namespace. The committed WBO port option defaults to null; 18000 is only an example, and final composition supplies the actual port. This corrects the previous Formal stage, which copied an older draft summary. Network policy stays explicit, including firewall source/destination restrictions. The source used an earlier containers name; the committed main framework is workloads. Source reviews and wiring do not establish deployed HTTP reachability.

## Virtualization and host resources

ThinkBook integrates a declarative libvirt Windows guest through NixVirt, with domain/network/storage XML templates, GPU SR-IOV, guest tooling and Samba sharing. Display experiments return to SPICE after GTK trials; virtualized Windows is a host-owned workload/resource rather than another NixOS host profile. Mount policy distinguishes Windows and shared filesystems, with the Windows partition mounted read-only at this horizon. Static configuration does not establish a successful guest boot, GPU assignment, filesystem safety under every external OS or runtime display result.

## Local packages and tools

The package framework discovers local packages, overlays and optional OS/HM module entry points, replacing the external self-nixpkgs collection. Local and namespace overlays are both retained; derivation attrsets must not be mistaken for namespaces. Package exports include the lazy-friendly legacyPackages collection rather than requiring every leaf to be a flat package output.

Pi's wrapper preserves outputs/metadata/resource layout, scopes startup-offline behavior and uses native extraPackages for fd/ripgrep. Startup offline does not prohibit model API calls. A missing wrapper-space error was corrected before a reported user rebuild; later skill changes lack fresh validation. Shared Git instructions reduce duplicated agent/command workflows, while permission enforcement remains outside skills. A proposed restricted Git-action extension was not implemented in that historical source; later Pi resource extensions are distinct functionality.

Clash's package-data override reportedly rebuilt, but the original missing geosite-list error was not proven resolved. Packaged versus runtime user-cache data remained ambiguous, and later MMDB download EOF was a separate failure. Keep the issue as an evidence gap, not a current reproduced incident or a guaranteed fixed defect. The local package collection becomes lazy, package HM entry naming is normalized, and agent context/skills are supplied through composable package resources. GAW and git-maintenance are project tool dependencies, not permission to bypass host policy. Treefmt configuration and its flake check are wired, without running them during reconstruction.

## Declaration registration

Private construction helpers in lib/flakeParts.configurations.nix discover OS internal options and HM interface fragments, return declaration modules and supply them to system construction. Registration is independent of share.enable; share owns common OS/HM behavior, while declarations remain available for selected consumers. A self-selecting share declaration file caused the earlier import overflow, so aggregation stays outside discovered declarations.

Public builder.nixosModules/homeModules additions and inline-flake aggregators were considered and withdrawn. User UID delivery, Feature recipients and other shared HM integrations remain distinct. Parent positions are not business-role declarations, and registration does not activate a Feature. No later share-disabled behavior test or fresh Nix success is established by this source.
