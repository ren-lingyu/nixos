#+TITLE: NixOS Configuration
#+AUTHOR: aRenCoco

* 简介
这是一个基于 Flake 的 NixOS 配置仓库.

* 架构约定
=flake.nix= 是最终组装层, 使用 flake-parts 声明每台系统的配置, 管理系统级 flake inputs, 并统一接入外部 NixOS/Home Manager modules 和 overlays. =pkgs/= 是独立的 package 子项目, 管理应用级 inputs, 依赖锁定和软件包输出. 具体配置由四类平级 profile 提供:

- =modules/hosts/= 描述主机身份, 硬件和主机拥有的资源. host 只通过 UID registry 声明可管理的用户, 不声明用户名或 user profile.
- =modules/users/= 描述 user profile 和个人 Home Manager 配置. user 不决定自己属于哪台 host.
- =modules/features/= 描述可复用的功能实现, 可同时提供 OS 和 HM 模块.
- =modules/workloads/= 描述按 host 需要启用的服务型 workload.

=modules/share/= 提供公共系统与用户配置, 与其他模块一样由最终配置显式启用. profile 选择, UID 绑定与外部依赖注入由 =flake.nix= 负责; 模块检查自己的依赖是否满足, 不替最终配置启用其他 profile. =lib/= 提供公共类型, 模块发现, 配置适配和系统构造函数, 在模块参数中名为 =llib=.

* Option 和组装协议
** Configuration 与 metadata
=modules/= 下包含 =os/default.nix= 或 =hm/default.nix= 的目录会被识别为模块. 两侧实现是统一目录约定, 模块之间不允许嵌套. 模块根目录的 =default.nix= 是可选的 NixOS 配置补充, 不再承担模块发现入口的职责.

从 =modules/_options.fp.nix= 到模块目录沿途的 =_options.fp.nix= 共同定义 schema, 分为 =configuration= 和 =metadata= 两部分. =configuration= 用于 flake-parts 层的 =nixosConfigurations.<system>.modules=; =metadata= 用于 =moduleRegistry.<kind>.<name>.metadata=. 模块的 =_metadata.fp.nix= 提供静态 metadata 值. =.fp.nix= 标识解释文件的配置层; metadata 文件仍返回普通 Nix 属性集, 不要求成为 flake-parts module. =_validators.fp.nix= 提供检查已求值 FP 数据的谓词函数, 由两个 FP option 的 =apply= 执行.

仓库使用 =_options.<system>.nix= 标识按约定发现的 option declaration 文件: =fp= 对应 flake-parts, =os= 对应 NixOS, =hm= 对应 Home Manager. 这些文件由仓库加载器发现, 文件名标识解释环境, 不限定声明的 option namespace. 三者保留各自接口: FP 返回 configuration/metadata 声明分支, OS 返回原生 NixOS module, HM 返回以模块名和求值上下文为参数的声明片段. 统一命名不要求统一返回值结构或函数签名.

share 没有 profile 名这一层, 对应 =nixosConfigurations.<system>.modules.share= 和 =moduleRegistry.share.metadata=.

=moduleRegistry= 同时登记模块需要的外部 =nixosModules=, =homeModules= 和 =nixpkgsOverlays=. =nixosBuilder= 提供 =nixosSystem= 构造函数, Home Manager 集成模块和公共 =specialArgs=. =llib.flakeParts.mkNixosConfigurations= 将配置集合转换为最终 =flake.nixosConfigurations=.

** FP validator 协议
=_validators.fp.nix= 是返回属性集的普通 Nix 函数, 不属于 Nix module. =metadata= 和 =configuration= 两个分支均可省略; 已声明的分支必须是返回布尔值的函数. =true= 表示通过, =false= 表示失败; 可以通过 =assert lib.assertMsg= 或 =throw= 提供具体诊断. 非布尔返回值, 未知分支或无效文件结构都会被拒绝.

#+begin_src nix
{ path }:
{
  metadata = { lib, llib, registry, ... }: true;
  configuration = { lib, llib, name, configuration, registry, ... }: true;
}
#+end_src

导入声明时仅传入文件所属目录的 =path=, 例如 =[ "modules" "features" "niri" ]=. 不隐式提供 FP =config/options= 或 OS/HM =config=. 执行分支时显式传入 =lib=, =llib= 和合并后的 Registry 或单个系统的 FP configuration; 文件位置表示约束的归属, 不限制其只能检查同目录的数据.

=llib.modules.discoverValidatorFiles= 基于现有 =discoverModules= descriptors 收集路径前缀中的文件, 包括 =modules/= 根级, 类别级及模块级. 不搜索 =os/= 或 =hm/=; 中间层文件可缺省. 文件按目录深度及同层路径顺序排列, 去重后每个文件在一次验证边界中至多执行一次. 各文件的约束按逻辑与组合, 不通过属性集覆盖合并函数.

=llib.flakeParts.mkValidatorApplications= 接收 =root=, =modulesDir= 和调用时的 =llib= 验证上下文, 生成与测试共用的两个 =apply= 函数. =moduleRegistry.apply= 用其参数中的 Registry 执行 =metadata= 验证并原样返回值, 不读取 =nixosConfigurations=. =nixosConfigurations.apply= 为各系统保留惰性验证: 消费该系统时执行 =configuration= 分支并返回原值, 不强制其他系统. 诊断包含文件, 分支以及配置分支的系统名称; =--show-trace= 保留谓词的具体错误上下文.

验证器只检查相关字段, 不修改数据, 不通过顶层已经处理过的同名 option 重新取得输入, 不对完整 Registry 或 configuration 使用 =deepSeq=. 外部 module, overlay 和 =functionTo= 值应保持惰性, 不应为了检查其存在而调用函数. 仅依赖 FP configuration 与 Registry metadata 的静态约束由所属目录的 validators 执行; 依赖最终 NixOS/Home Manager 状态的检查继续留在对应原生 module system 中.

静态约束按职责归属组织: =hosts/_validators.fp.nix= 检查所有 Host 的 number, monitor, UID registry 和 WireGuard endpoint/listenPort 关系, 并检查每个系统恰好启用一个 Host; =users/_validators.fp.nix= 检查 UID, username, home directory 和选中 Host 的 UID 注册关系; =features/_validators.fp.nix= 只对启用且具有 HM 实现的 Feature 检查 =allowUidList=. 非空 User UID 的下界对禁用 User 同样适用, Host 可以登记未分配给启用 User 的 UID, 禁用 Feature 可以保留非空默认接收列表.

Niri, Greeter, Proxy 和 ThinkBook 在各自目录维护静态约束. Niri 的子功能父级依赖与互斥, Proxy 四个子功能的父级依赖及仅 clash-verge/mihomo 的互斥, ThinkBook Flatpak 的父级依赖会在父模块禁用时仍被检查. Niri 和 Greeter 启用时要求选中 Host 恰有一个默认 monitor. Noctalia 对实际系统服务的要求, Greeter 会话包的 =meta.mainProgram= 与 provider 非空检查, 以及 HM 的 SOPS/provider/terminal-exec 检查仍保留为原生 assertions.

** =enable= 与 =existModule=
=nixosConfigurations.<system>.modules.<kind>.<name>.enable= 表示在当前最终配置中启用该 profile, 默认关闭. =existModule.{os,hm}= 由模块发现 descriptor 自动派生, 是内部只读布尔值: =true= 表示对应实现存在, =false= 表示不存在, 不再使用 =null= 或手动 metadata 声明.

模块发现要求至少存在 =os/default.nix= 或 =hm/default.nix= 之一; 两侧都不存在的目录不会作为模块进入 Registry. =moduleRegistry.<kind>.<name>.metadata.existModule= 与 NixOS 的 =config.modules.<kind>.<name>.existModule= 保持原有访问路径.

=existModule= 与 profile 的 =enable= 无关, 也不表示 Home Manager 本身是否存在. 构建函数根据目录发现结果加载已启用模块的实现; 派生 metadata 也参与 feature 的默认 HM 用户选择.

NixOS 的 =config.modules= 是外层 configuration 经适配后与 metadata 合并的只读视图; Home Manager 通过 =osConfig.modules= 读取它. 禁用父模块时, 其实现和外部集成不加载, 子选项不会单独启用实现.

** User 与 UID
=modules.users= 以 profile 名为 key, =username= 是可与 profile 名不同的登录名. host 的 =moduleRegistry.hosts.<host>.metadata.users= 登记可用 UID; =flake.nix= 在最终组装时完成绑定:

#+begin_src nix
nixosConfigurations.nixos.modules.users.lingyu.uid =
  config.moduleRegistry.hosts.thinkbook.metadata.users."1000";
#+end_src

FP User validator 保证启用的 user 已绑定 UID, 启用用户的用户名和 UID 各自唯一, 且 UID 已在启用 host 中登记. host registry 可以包含尚未绑定给当前 user profile 的 UID. NixOS 与 Home Manager 实现读取适配后的 =modules.hosts.<host>.users= 和 =modules.users.<profile>=.

** Feature 的 HM 送达
=modules.features.<name>.allowUidList= 指定应向哪些 Home Manager 用户导入该 feature 的 =hm/default.nix= 及 registry 中的 =homeModules=. 当 feature 存在 HM 模块时, 它默认包含所有已启用且已绑定 UID 的 user; 否则默认为空. 启用且声明 HM 实现的 feature 会校验列表不能包含重复 UID, 也不能引用未分配给启用 user 的 UID.

user profile 的 HM 实现导入到自身绑定的 UID. 其他类别的已启用模块, 包括 share 和 host, 将 HM 实现及外部 HM 集成加入 =home-manager.sharedModules=.

** =moduleInternals= 与 =moduleInterfaces=
=moduleInternals= 保存 NixOS 求值阶段产生的内部状态, 例如启用 host 的显示器信息和 shell 包. 声明位于各模块的 =os/_options.os.nix=; HM 实现通过 =osConfig.moduleInternals= 读取这些状态.

=moduleInterfaces= 是 Home Manager 模块之间的内部通信命名空间. 声明位于各模块的 =hm/_options.hm.nix=, 注册到每个 Home Manager 用户自己的 option 合并范围中. user profile 可以通过 =moduleInterfaces.<kind>.<name>.*= 向 feature 提供 per-user 内部数据; 当前 sops feature 用它接收 per-user SOPS 输入, agent feature 用它接收 provider 配置和 API key 文件路径.

=mkNixosSystem= 通过构建库的私有生成函数统一加载这两类声明, 不依赖 =share.enable=. 声明加载不表示对应功能已启用. niri 与 x11-session 直接向 =moduleInternals.features.greeter.sessionPackages= 贡献会话包, niri 使用 =mkBefore= 保持优先顺序; greeter 校验包的 =meta.mainProgram= 并消费列表.

** 导入与配置适配
最终模块列表直接由已求值的 flake-parts configuration 生成. =mkNixosSystem= 导入类别公共模块, 已启用 profile 的 OS 实现和可选根 =default.nix=, 并收集 registry 中的外部模块与 overlays. 这避免了在 NixOS 同一求值层根据 =config= 决定 =imports= 的循环依赖.

依赖最终 NixOS =config= 或 =pkgs= 的配置值通过 =functionTo= 类型延迟解析, 例如:

#+begin_src nix
nixosConfigurations.nixos.modules.features.editor.emacs.programs.package =
  { pkgs, ... }: pkgs.emacs31-pgtk;
#+end_src

适配器按 option schema 解析 =functionTo= 值和 submodule, 保留其他值中的函数. 公共与每台系统的 =specialArgs= 合并后分别传入 NixOS 和 Home Manager.

仓库根目录放置系统 flake 入口, lock 文件, README, package 子项目和模块目录. 根 =flake.nix= 使用 =flake-parts= 组织系统输出, 包括 =nixosConfigurations=, =checks=, =devShells= 和 =formatter=; 本地软件包, overlays 和附带的 OS/HM 模块由 =pkgs/flake.nix= 导出. 根 =nixpkgs= 使用 =nixos-unstable=, 并启用 =nix-command= 与 =flakes=.

根 flake inputs 按使用位置集中传递:
- =nixpkgs=: 提供最终系统与 =perSystem= 的 package set, 也是多个 inputs 的 =follows= 目标.
- =local-nixpkgs=: 通过 =path:./pkgs= 引用 package 子项目, 将其 =share= 和 =editor= overlays/modules 注入对应 Registry 条目; 子项目的 =treefmt-nix= 跟随根输入.
- =flake-parts=: 组装 flake outputs, =nixpkgs-lib= 跟随根 =nixpkgs=.
- =treefmt-nix=: 提供 formatter 与格式检查, 启用 nixfmt, shfmt 和 prettier.
- =home-manager=: 通过 =nixosBuilder.homeManager= 导入每台系统.
- =agenix= 和 =agenix-rekey=: 提供 age secret 与 rekey module; =agenix-rekey.agePackage= 使用本仓库的 =rage-armored=.
- =sops-nix=: 注入 sops feature 所需的 NixOS 与 Home Manager modules.
- =niri-flake=: 注入 niri feature 所需的 overlay 和 Home Manager modules.
- =nix-flatpak=: 注入 thinkbook host 的 Flatpak module.
- =nixvirt=: 注入 thinkbook host 的 NixVirt module.
- =nixos-wsl=: 注入 wsl host 的 NixOS-WSL module.
- =nixos-anywhere= 和 =disko=: 提供部署 devShell 与 aliyun host 的 disko module; =disko= 通过 =follows= 复用 =nixos-anywhere/disko=.

[[file:./lib/default.nix][lib/default.nix]] 导出 =llib= 的公共命名空间:
- =types=: 显示器及显示器集合类型.
- =modules=: 模块与 validator 文件发现, option tree/schema 组织及框架结构检查.
- =hosts=: host 选择与 WireGuard 拓扑生成.
- =features.sops=: per-user SOPS 输入处理.
- =flakeParts=: 配置适配, 系统构造与 =mkValidatorApplications= 验证组合/执行; =flakeParts.types= 声明 registry, builder 和系统配置类型.

[[file:./lib/flakeParts.configurations.nix][flakeParts.configurations.nix]] 私有封装内部与接口 options 的生成, 并在系统构造时统一加载.

=lib/default.nix= 按实际依赖逐项构造各 flakeParts 子库, 不注入递归的整库 =llib=. =moduleRegistry= 类型函数在调用时通过 =root=, =modulesDir= 和 =llib= 接收模块路径及 metadata 声明上下文, validator 在 =mkValidatorApplications= 调用时接收验证上下文; 两者均与库的构造依赖分开.

通用库中的 =assert= / =throw= 检查框架结构与函数前置条件, 例如发现路径范围, 禁止嵌套模块及 configuration/metadata 顶层字段不相交. 这些检查保留在通用库, 模块业务静态约束由所属 =_validators.fp.nix= 维护, 最终 NixOS/HM 状态相关检查使用原生 assertions.

[[file:./pkgs/flake.nix][pkgs/flake.nix]] 使用独立的 inputs 和 [[file:./pkgs/flake.lock][flake.lock]] 管理应用依赖, =nixpkgs= 使用 =nixpkgs-unstable=, 不跟随根系统的 =nixpkgs=. 应用依赖可相对独立地维护和更新; 根 flake 仍决定模块启用, overlay 接入和最终系统构建. 根消费子项目时还通过自己的 lock graph 记录其依赖, 更新子项目后也应核对根消费的依赖状态.

子项目 inputs 包括:
- =personal-nixpkgs=: 提供通用 package library, 其 =nixpkgs=, =flake-parts= 和 =treefmt-nix= 跟随子项目对应输入.
- =flake-parts= 和 =treefmt-nix=: 组织子 flake 及其应用依赖的 =follows= 关系. =treefmt-nix= 当前未在子项目中配置独立 formatter/checks.
- =emarccs=, =lem= 和 =nixvim=: 提供 editor 所需的 overlays 和 Home Manager module.
- =git-agent-workflow=: 通过 =share= overlay 提供持久记忆工具.
- =lean4-nix=: 通过 =share= overlay 提供 =lean4= 二进制包.
- =zotero-fix-nixpkgs=: 固定 nixpkgs revision, 通过 =share= overlay 提供对应 =zotero= 包.

=pkgs/flake.nix= 将 =personal-nixpkgs.lib= 与 [[file:./pkgs/lib/default.nix][pkgs/lib/default.nix]] 的本地扩展通过 =mergeAttrsRecursive { allowOverrides = false; }= 合并为子项目的 =llib=, 禁止覆盖同名定义. 通用 =llib.packages= 由外部库提供; 本地扩展入口当前为空, 子项目 =llib= 与根 =llib= 分开. [[file:./pkgs/pkgs/default.nix][pkgs/pkgs/default.nix]] 使用它生成本地包集合, overlays 和 OS/HM 模块入口. =package.nix= 定义包, =overlay.nix= 注入包或命名空间; =os/default.nix= 和 =hm/default.nix= 提供包附带的模块. =mkOverlays= 按目录返回扩展集合, 再组合成本地 overlay 分组; 非 =default= 分组必须互不重叠, 且都是 =default= 的子集.

子 flake 当前提供 =x86_64-linux= 软件包输出及以下集成入口:
- =legacyPackages.x86_64-linux=: 先通过 =appendOverlays= 将 =overlays.default= 的本地扩展应用到子项目的 package set, 再调用 =mkLegacyPackages=, 以 =overlayFile = "overlay.nix"= 指定发现入口. =share= 和 =editor= 的上游应用集成仍由相应 overlays 提供.
- =overlays.default=: 包含全部本地包扩展.
- =overlays.share=: 本地包扩展中排除 =rage-armored=, 并加入 GAW, Lean 和 Zotero 的集成.
- =overlays.editor=: 组合 emarccs 和 Lem 的 overlays, 并为 Lem 补充依赖及桌面入口.
- =nixosModules.share= 和 =homeModules.share=: 汇集包附带的 OS/HM 模块.
- =homeModules.editor=: 提供 Nixvim Home Manager module.

根 flake 通过 =moduleRegistry.share= 和 =moduleRegistry.features.editor= 接入对应 overlays/modules, 由现有模块启用与 HM 用户分配规则决定加载范围. rekey 工具使用 =(pkgs.extend inputs.local-nixpkgs.overlays.default).rage-armored=, 在根 =perSystem= 的 package set 上构造 wrapper.

本地 package 包括:
- =codex=: 为 Codex wrapper 补充 Python/PyYAML 运行环境.
- =difftastic=: 应用 Haskell parser 修复.
- =git-maintenance=: 安装仓库维护 skill.
- =pi-coding-agent=: 为 Pi 设置离线运行环境.
- =piPackages=: 提供 agentic search, context, web search 和 workspace history 扩展, 以及相应依赖处理和安装检查文件.
- =rage-armored=: 基于 =pkgs.rage= 安装 wrapper, 将原始二进制保留为 =rage-unwrapped=, 并在常规加密调用中默认注入 =--armor=; 同时用作 =agenix-rekey.agePackage=.
- =texlivePackages=: 扩展 TeX Live 包集合, 包括 =luadraw=.
- =wayfile=: 提供 Wayfile 包和 Home Manager module.

[[file:./modules/features/_validators.fp.nix][modules/features/_validators.fp.nix]] 在 FP 层校验 feature 的 HM 用户选择. =_options.fp.nix= 定义公共 =allowUidList= schema; 发现, option tree 生成与 HM 送达由构建库统一处理.

每个 feature 的实现可用性由目录发现结果派生, 通过可选的 =_options.fp.nix= 定义配置 schema, 按需提供 =os/= 和 =hm/= 实现. 可选根 =default.nix= 保存跨实现的内部状态, 会话包贡献或断言.

[[file:./modules/hosts/default.nix][modules/hosts/default.nix]] 导入 boot-manager, identity, shared 和 WireGuard 相关通用模块. =_validators.fp.nix= 在 metadata 分支校验全部 Host 的静态属性, 在 configuration 分支确保恰好启用一个 host. =_options.fp.nix= 定义 host metadata schema.

[[file:./modules/hosts/boot-manager.nix][modules/hosts/boot-manager.nix]], [[file:./modules/hosts/identity.nix][modules/hosts/identity.nix]], [[file:./modules/hosts/shared.nix][modules/hosts/shared.nix]] 和 [[file:./modules/hosts/wireguard.nix][modules/hosts/wireguard.nix]] 分别消费 host metadata, 生成 boot manager, identity, shared capability 和 WireGuard topology/secret 的配置.

各 host 的 =_metadata.fp.nix= 由 registry 的 metadata 子模块加载, 用于声明 UID registry, monitor, public IP, WireGuard 和 identity metadata. =ssh.private.age= 与 =wireguard.private.age= 分别保存该 host 的加密 SSH host private key 与 WireGuard private key, 并由 =_metadata.fp.nix= 引用.
