#+TITLE: NixOS Configuration
#+AUTHOR: aRenCoco

* 简介
这是一个基于 Flake 的 NixOS 配置仓库.

* 架构约定
=flake.nix= 是最终组装层, 统一管理 flake inputs、外部 NixOS/Home Manager modules、overlays 和 =nixosConfigurations=. 具体配置由三类平级 profile 提供:

- =modules/hosts/= 描述主机身份、硬件和主机拥有的资源. host 只通过 UID registry 声明可管理的用户, 不声明用户名或 user profile.
- =modules/users/= 描述 user profile 和个人 Home Manager 配置. user 不决定自己属于哪台 host.
- =modules/features/= 描述可复用的功能实现, 可同时提供 OS 和 HM 模块.

三类 profile 只决定各自负责的事务. profile 选择、UID 绑定与外部依赖注入由 =flake.nix= 负责. =lib/= 则提供公共类型、断言生成器和模块聚合函数, 在模块参数中名为 =llib=.

* Option 和组装协议
** =enable= 与 =existModule=

=modules.<kind>.<name>.enable= 表示在当前最终配置中启用该 profile. =existModule.{os,hm}= 则是 profile 根入口声明的内部事实信息:

- =true= 表示对应子模块存在.
- =false= 表示对应子模块不存在.
- =null= 表示 profile 根入口尚未声明模块性质.

=existModule= 不控制 profile 是否启用, 也不表示 Home Manager 本身是否存在. 统一断言会将它与 =os/default.nix= 和 =hm/default.nix= 的实际情况比较; =existModule.hm= 还用于决定是否向 Home Manager 用户送达该 profile 的 HM 实现.

** User 与 UID
=modules.users= 以 profile 名为 key, =username= 是可与 profile 名不同的登录名. host 以 =modules.hosts.<host>.users."<uid>" = <uid>= 登记可用 UID; =flake.nix= 在最终组装时完成绑定:

#+begin_src nix
modules.users.lingyu.uid = config.modules.hosts.thinkbook.users."1000";
#+end_src

断言保证启用的 user 已绑定 UID、启用用户的用户名和 UID 各自唯一, 且 UID 已在启用 host 中登记. host registry 可以包含尚未绑定给当前 user profile 的 UID.

** Feature 的 HM 送达
=modules.features.<name>.allowUidList= 指定应向哪些 Home Manager 用户导入该 feature 的 =hm/default.nix=. 当 feature 存在 HM 模块时, 它默认包含所有已启用且已绑定 UID 的 user; 否则默认为空. 列表不能包含重复 UID, 也不能引用未分配给启用 user 的 UID.

** =moduleInterfaces=
=moduleInterfaces= 是 Home Manager 模块之间的内部通信命名空间. =modules/default.nix= 自动发现 =modules/<kind>/<name>/hm/interface-options.nix=, 并将定义注册到每个 Home Manager 用户自己的 option 合并范围中. user profile 可以通过 =moduleInterfaces.<kind>.<name>.*= 向 feature 提供 per-user 内部数据; 当前 sops feature 用它接收 per-user SOPS 输入, agent feature 用它接收 provider API key 文件路径.

** 导入时机
NixOS =imports= 无法根据 =config= 动态决定. host 和 feature 根入口由 =self.modules.*= wrapper 在 =flake.nix= 中静态导入; user 根入口由 =modules/users/default.nix= 统一静态导入. wrapper 同时引入所需 flake inputs, 避免外部依赖和 =inputs.<name>= 命名散落到 profile 实现中.

Home Manager 模块可以通过 =home-manager.users.<uid>.imports= 合并, 因此 HM 实现可根据 =enable=、=existModule.hm= 和 =allowUidList= 进行条件送达. =self.modules.base= 通过 =_module.args.llib= 向 NixOS 模块传递本地函数库, 并通过 =home-manager.extraSpecialArgs= 将它传递给 Home Manager 模块.

仓库根目录放置 flake 入口, lock 文件, README, 本地 package 集合和模块目录. =flake.nix= 使用 =flake-parts= 组织输出, 定义 =nixosConfigurations=, =packages=, =checks= 和 =devShells=. =nixpkgs= 使用 =nixos-unstable=, 并启用 =nix-command= 与 =flakes=.

根 flake inputs 按使用位置集中传递:
- =nixpkgs=: 提供最终系统与 =perSystem= 的 package set, 也是多个 inputs 的 =follows= 目标.
- =self-nixpkgs=: 作为 overlay 和 Home Manager shared module 注入基础模块.
- =emarccs=: 作为 overlay 注入基础模块.
- =flake-parts=: 组装 flake outputs.
- =home-manager=: 作为 NixOS module 导入基础模块, 并作为 =agenix= 的 =home-manager= follows 目标.
- =agenix= 和 =agenix-rekey=: 提供 age secret 与 rekey module; =agenix-rekey.agePackage= 使用本仓库的 =rage-armored=.
- =sops-nix=: 注入 sops feature 所需的 NixOS 与 Home Manager modules.
- =nixvim= 和 =lem=: 注入 editor feature 所需的 Home Manager module 与 overlay.
- =niri-flake= 和 =noctalia=: 注入 niri feature 所需的 overlay 和 Home Manager modules.
- =nix-flatpak=: 注入 thinkbook host 的 Flatpak module.
- =nixos-wsl=: 注入 wsl host 的 NixOS-WSL module.
- =nixos-anywhere= 和 =disko=: 提供部署 devShell 与 aliyun host 的 disko module; =disko= 通过 =follows= 复用 =nixos-anywhere/disko=.

[[file:./modules/features/default.nix][modules/features/default.nix]] 按功能领域组织 NixOS 与 home-manager 模块, 自动发现含 =default.nix= 的 feature 目录, 定义 =modules.features.*= option, 并把启用的 HM feature 导入到对应用户.

所有 feature 都由 [[file:./modules/features/default.nix][modules/features/default.nix]] 自动发现, 并以 =modules.features.<name>= option 暴露. 最终配置通过 =modules.features.<name>.enable= 按需启用 feature; 含 HM 模块的 feature 会按 =allowUidList= 导入到对应 UID 的 Home Manager 配置.

每个 feature 以 =default.nix= 作为根入口, 并按需使用 =os/= 和 =hm/= 存放系统级与用户级实现. =extra-options.nix= 扩展 feature options; =hm/interface-options.nix= 定义 per-user 的内部 HM 通信接口. 目录可以只包含适用的子模块, 并由 =existModule= 断言核对实际结构.
