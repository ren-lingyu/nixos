#+TITLE: NixOS Configuration
#+AUTHOR: aRenCoco

* 简介
这是一个基于 Flake 的 NixOS 配置仓库.

* 架构约定
=flake.nix= 是最终组装层, 通过 =personal-nixpkgs.lib.mkFlake= 组织 flake-parts 配置, 声明每台系统, 管理系统级 flake inputs, 导出本地软件包, 并接入项目级 NixOS/Home Manager modules 和 overlays. =pkgs/= 是独立的 package 子项目, 管理应用及 Feature 专用 inputs, 包定义和集成输出, 根 =flake.lock= 记录系统消费的依赖版本. 具体配置由四类平级 profile 提供:

- =modules/hosts/= 描述主机身份, 硬件和主机拥有的资源. host 只通过 UID registry 声明可管理的用户, 不声明用户名或 user profile.
- =modules/users/= 描述 user profile 和个人 Home Manager 配置. user 不决定自己属于哪台 host.
- =modules/features/= 描述可复用的功能实现, 可同时提供 OS 和 HM 模块.
- =modules/workloads/= 描述按 host 需要启用的服务型 workload.

=modules/share/= 提供公共系统与用户配置, 与其他模块一样由最终配置显式启用. profile 选择, UID 绑定与外部依赖注入由 =flake.nix= 负责; 模块检查自己的依赖是否满足, 不替最终配置启用其他 profile. =lib/= 提供公共类型, 模块发现, 配置适配和系统构造函数, 在模块参数中名为 =llib=.

* Option 和组装协议
** Configuration 与 metadata
=modules/= 下包含 =os/default.nix= 或 =hm/default.nix= 的目录会被识别为模块. 两侧实现是统一目录约定, 模块之间不允许嵌套. 模块根目录的 =default.nix= 是可选的 NixOS 配置补充, 不再承担模块发现入口的职责.

从 =modules/_options.fp.nix= 到模块目录沿途的 =_options.fp.nix= 共同定义 schema, 分为 =configuration= 和 =metadata= 两部分. =configuration= 用于 flake-parts 层的 =nixosConfigurations.<system>.modules=; =metadata= 用于 =moduleRegistry.<kind>.<name>.metadata=. 模块的 =_metadata.fp.nix= 提供静态 metadata 值. =.fp.nix= 标识解释文件的配置层; metadata 文件仍返回普通 Nix 属性集, 不要求成为 flake-parts module. =_validators.fp.nix= 提供检查已求值 FP 数据的谓词函数, 由两个 FP option 的 =apply= 执行.

仓库使用 =_options.<system>.nix= 标识按约定发现的 option declaration 文件: =fp= 对应 flake-parts, =os= 对应 NixOS, =hm= 对应 Home Manager. 这些文件由仓库加载器发现, 文件名标识解释环境, 不限定声明的 option namespace. 三者保留各自接口: FP 返回 configuration/metadata 声明分支, OS 返回原生 NixOS module, HM 返回以模块名和求值上下文为参数的声明片段. 统一命名不要求统一返回值结构或函数签名.

share 没有 profile 名这一层, 对应 =nixosConfigurations.<system>.modules.share= 和 =moduleRegistry.share.metadata=.

=moduleRegistry= 同时登记模块需要的外部 =nixosModules=, =homeModules= 和 =nixpkgsOverlays=. =nixosBuilder= 提供 =nixosSystem= 构造函数, Home Manager 集成模块和公共 =specialArgs=. =llib.flakeParts.mkNixosConfigurations= 将配置集合转换为最终 =flake.nixosConfigurations=.

** FP validator 协议
=_validators.fp.nix= 是返回属性集的普通 Nix 函数, 不属于 Nix module. =metadata= 和 =configuration= 两个分支均可省略; 已声明的分支必须是返回布尔值的函数. =true= 表示通过, =false= 表示失败; 可以通过 =assert lib.assertMsg= 或 =throw= 提供具体诊断. 非布尔返回值, 未知分支或无效文件结构都会被拒绝.

#+begin_src nix
{ path }:
{
  metadata = { lib, llib, registry, ... }: true;
  configuration = { lib, llib, name, configuration, registry, ... }: true;
}
#+end_src

导入声明时仅传入文件所属目录的 =path=, 例如 =[ "modules" "features" "niri" ]=. 不隐式提供 FP =config/options= 或 OS/HM =config=. 执行分支时显式传入 =lib=, =llib= 和合并后的 Registry 或单个系统的 FP configuration; 文件位置表示约束的归属, 不限制其只能检查同目录的数据.

=llib.modules.discoverValidatorFiles= 基于现有 =discoverModules= descriptors 收集路径前缀中的文件, 包括 =modules/= 根级, 类别级及模块级. 不搜索 =os/= 或 =hm/=; 中间层文件可缺省. 文件按目录深度及同层路径顺序排列, 去重后每个文件在一次验证边界中至多执行一次. 各文件的约束按逻辑与组合, 不通过属性集覆盖合并函数.

=llib.flakeParts.mkValidatorApplications= 接收 =modules= 目录和调用时的 =llib= 验证上下文, 生成与测试共用的两个 =apply= 函数. =moduleRegistry.apply= 用其参数中的 Registry 执行 =metadata= 验证并原样返回值, 不读取 =nixosConfigurations=. =nixosConfigurations.apply= 为各系统保留惰性验证: 消费该系统时执行 =configuration= 分支并返回原值, 不强制其他系统. 诊断包含文件, 分支以及配置分支的系统名称; =--show-trace= 保留谓词的具体错误上下文.

验证器只检查相关字段, 不修改数据, 不通过顶层已经处理过的同名 option 重新取得输入, 不对完整 Registry 或 configuration 使用 =deepSeq=. 外部 module, overlay 和 =functionTo= 值应保持惰性, 不应为了检查其存在而调用函数. 仅依赖 FP configuration 与 Registry metadata 的静态约束由所属目录的 validators 执行; 依赖最终 NixOS/Home Manager 状态的检查继续留在对应原生 module system 中.

静态约束按职责归属组织: =hosts/_validators.fp.nix= 检查所有 Host 的 number, monitor, UID registry 和 WireGuard endpoint/listenPort 关系, 并检查每个系统恰好启用一个 Host; =users/_validators.fp.nix= 检查 UID, username, home directory 和选中 Host 的 UID 注册关系; =features/_validators.fp.nix= 只对启用且具有 HM 实现的 Feature 检查 =allowUidList=. 非空 User UID 的下界对禁用 User 同样适用, Host 可以登记未分配给启用 User 的 UID, 禁用 Feature 可以保留非空默认接收列表.

Niri, Greeter, Proxy 和 ThinkBook 在各自目录维护静态约束. Niri 的子功能父级依赖与互斥, Proxy 四个子功能的父级依赖及仅 clash-verge/mihomo 的互斥, ThinkBook Flatpak 的父级依赖会在父模块禁用时仍被检查. Niri 和 Greeter 启用时要求选中 Host 恰有一个默认 monitor. Noctalia 对实际系统服务的要求, Greeter 会话包的 =meta.mainProgram= 与 provider 非空检查, 以及 HM 的 SOPS/provider/terminal-exec 检查仍保留为原生 assertions.

** =enable= 与 =existModule=
=nixosConfigurations.<system>.modules.<kind>.<name>.enable= 表示在当前最终配置中启用该 profile, 默认关闭. =existModule.{os,hm}= 由模块发现 descriptor 自动派生, 是内部只读布尔值: =true= 表示对应实现存在, =false= 表示不存在, 不再使用 =null= 或手动 metadata 声明.

模块发现要求至少存在 =os/default.nix= 或 =hm/default.nix= 之一; 两侧都不存在的目录不会作为模块进入 Registry. =moduleRegistry.<kind>.<name>.metadata.existModule= 与 NixOS 的 =config.modules.<kind>.<name>.existModule= 保持原有访问路径.

=existModule= 与 profile 的 =enable= 无关, 也不表示 Home Manager 本身是否存在. 构建函数根据目录发现结果加载已启用模块的实现; 派生 metadata 也参与 feature 的默认 HM 用户选择.

NixOS 的 =config.modules= 是外层 configuration 经适配后与 metadata 合并的只读视图; Home Manager 通过 =osConfig.modules= 读取它. 禁用父模块时, 其实现和外部集成不加载, 子选项不会单独启用实现.

** User 与 UID
=modules.users= 以 profile 名为 key, =username= 是可与 profile 名不同的登录名. host 的 =moduleRegistry.hosts.<host>.metadata.users= 登记可用 UID; =flake.nix= 在最终组装时完成绑定:

#+begin_src nix
nixosConfigurations.nixos.modules.users.lingyu.uid =
  config.moduleRegistry.hosts.thinkbook.metadata.users."1000";
#+end_src

FP User validator 保证启用的 user 已绑定 UID, 启用用户的用户名和 UID 各自唯一, 且 UID 已在启用 host 中登记. host registry 可以包含尚未绑定给当前 user profile 的 UID. NixOS 与 Home Manager 实现读取适配后的 =modules.hosts.<host>.users= 和 =modules.users.<profile>=.

** Feature 的 HM 送达
=modules.features.<name>.allowUidList= 指定应向哪些 Home Manager 用户导入该 feature 的 =hm/default.nix= 及 registry 中的 =homeModules=. 当 feature 存在 HM 模块时, 它默认包含所有已启用且已绑定 UID 的 user; 否则默认为空. 启用且声明 HM 实现的 feature 会校验列表不能包含重复 UID, 也不能引用未分配给启用 user 的 UID.

user profile 的 HM 实现导入到自身绑定的 UID. 其他类别的已启用模块, 包括 share 和 host, 将 HM 实现及外部 HM 集成加入 =home-manager.sharedModules=.

** 原生 Feature 接口与过渡声明
客制化功能使用 =features.<name>= 原生 options. 每个实际存在的 NixOS/HM 模块各自声明默认 =false= 的 =features.<name>.enable=. 导入模块使 options 可用, 显式启用后才提供功能配置. OS 与 HM 独立启用, Shell 的系统 shell 状态与包、Niri 的系统包等依赖仍通过原生接口表达.

当前 root registry 负责按 FP 配置选择系统和 UID, 并在收到模块的作用域显式启用、映射配置. 这些映射、现有 discovery markers 和 HM 分配协议属于第一阶段的过渡接线.

=mkNixosSystem= 仍统一加载原有声明, 独立于 =share.enable=. SOPS 和 Agent 的 =hm/_options.hm.nix= 暂时保留 =moduleInterfaces=, 供现有 user profile 描述账户 secrets、provider 和 API key 路径. 由 root 接线映射已定义字段. Niri 和 X11 分别输出实际 session package, root 将已启用 provider 的包送给 Greeter, 使用 =mkBefore= 保持 Niri 优先.

** 导入与配置适配
最终模块列表直接由已求值的 flake-parts configuration 生成. =mkNixosSystem= 导入类别公共模块, 已启用 profile 的 OS 实现和可选根 =default.nix=, 并收集 registry 中的外部模块与 overlays. 这避免了在 NixOS 同一求值层根据 =config= 决定 =imports= 的循环依赖.

依赖最终 NixOS =config= 或 =pkgs= 的配置值通过 =functionTo= 类型延迟解析, 例如:

#+begin_src nix
nixosConfigurations.nixos.modules.features.editor.emacs.programs.package =
  { pkgs, ... }: pkgs.emacs31-pgtk;
#+end_src

适配器按 option schema 解析 =functionTo= 值和 submodule, 保留其他值中的函数. 公共与每台系统的 =specialArgs= 合并后分别传入 NixOS 和 Home Manager.

仓库根目录放置系统 flake 入口, lock 文件, README, package 子项目和模块目录. 根 =flake.nix= 使用 =personal-nixpkgs.lib.mkFlake inputs.nixpkgs= 组织输出, 包括 =nixosConfigurations=, =legacyPackages=, =checks=, =devShells= 和 =formatter=; overlays 和包附带的 OS/HM 模块由 =pkgs/flake.nix= 导出. 根 =nixpkgs= 使用 =nixos-unstable=, 并启用 =nix-command= 与 =flakes=.

根 flake 和 package 子项目均向 =mkFlake= 传入接收 =lib= 的配置回调, 用该参数导入本地库, 并声明 =moduleLocation = __curPos.file;=. 根回调提供 =llib= 和 =specialArgs.rootPath=, 子项目回调提供自己的 =llib= 与 =lpkgs=.

根 flake inputs 按使用位置集中传递:
- =nixpkgs=: 提供最终系统与 =perSystem= 的 package set, 也是多个 inputs 的 =follows= 目标.
- =personal-nixpkgs=: 提供 =mkFlake= 组装入口与 =llib.tests= 测试组织接口, 其 =nixpkgs= 跟随根输入; 与 package 子项目中的同名输入在根 lock graph 中分别记录版本. =flake-parts= 和 =treefmt-nix= 由该输入管理, 不再直接声明为根输入.
- =local-nixpkgs=: 通过 =path:./pkgs= 引用 package 子项目, 将其 Share overlays/modules 和 Feature module exports 注入对应 Registry 条目; =legacy= overlay 用于构造根 =perSystem= 的 package set 和 =legacyPackages= 输出.
- =home-manager=: 通过 =nixosBuilder.homeManager= 导入每台系统.
- =agenix= 和 =agenix-rekey=: 提供 age secret 与 rekey module; =agenix-rekey.agePackage= 使用本仓库的 =rage-armored=, =agenix-rekey= 的 =treefmt-nix= 跟随 =personal-nixpkgs/treefmt-nix=.
- =nix-flatpak=: 注入 thinkbook host 的 Flatpak module.
- =nixvirt=: 注入 thinkbook host 的 NixVirt module.
- =nixos-wsl=: 注入 wsl host 的 NixOS-WSL module.
- =nixos-anywhere= 和 =disko=: 提供部署 devShell 与 aliyun host 的 disko module; =disko= 通过 =follows= 复用 =nixos-anywhere/disko=, =nixos-anywhere= 的 =treefmt-nix= 跟随 =personal-nixpkgs/treefmt-nix=.

[[file:./lib/default.nix][lib/default.nix]] 导出 =llib= 的公共命名空间:
- =types=: 由根 flake 从 =pkgs/lib/= 引入的共享值类型, 包括显示器、SOPS secret 输入和默认编辑器.
- =modules=: 模块与 validator 文件发现, option tree/schema 组织及框架结构检查.
- =hosts=: host 选择与 WireGuard 拓扑生成.
- =flakeParts=: 配置适配, 系统构造与 =mkValidatorApplications= 验证组合/执行; =flakeParts.types= 声明 registry, builder 和系统配置类型.

根 flake 将本地库与 =personal-nixpkgs.lib.tests= 合并为运行时 =llib=, 不引入外部库的其他命名空间.

[[file:./lib/flakeParts.configurations.nix][flakeParts.configurations.nix]] 私有封装内部与接口 options 的生成, 并在系统构造时统一加载.

=lib/default.nix= 按实际依赖逐项构造各 flakeParts 子库, 不注入递归的整库 =llib=. =moduleRegistry= 类型函数在调用时通过 =modules= 和 =llib= 接收模块目录及 metadata 声明上下文. =nixosConfigurations= 类型函数显式接收 =modules=, =llib= 和 =registry=, 在声明上下文中保留 =moduleRegistry= 名称. validator 在 =mkValidatorApplications= 调用时接收验证上下文. 这些调用参数与库的构造依赖分开.

模块发现, 声明加载, validator 加载, FP 类型构造及 NixOS 构建统一接收 =modules= 目录. =discoverModules modules= 生成的逻辑路径始终以 =[ "modules" ]= 开头, 不从仓库根路径或目录实际名称推导; 声明与 validator 文件从传入目录定位. =builder.specialArgs= 中的运行时参数与该目录接口独立.

通用库中的 =assert= / =throw= 检查框架结构与函数前置条件, 例如发现目录本身不能作为模块, 禁止嵌套模块及 configuration/metadata 顶层字段不相交. 这些检查保留在通用库, 模块业务静态约束由所属 =_validators.fp.nix= 维护, 最终 NixOS/HM 状态相关检查使用原生 assertions.

[[file:./pkgs/flake.nix][pkgs/flake.nix]] 独立使用时由自身 inputs 声明应用依赖, =nixpkgs= 指向 =nixpkgs-unstable=. 根 flake 将 =local-nixpkgs= 的 =nixpkgs= 与 =personal-nixpkgs= 分别指向根输入, 并通过根 [[file:./flake.lock][flake.lock]] 记录其依赖版本, 仓库不跟踪 =pkgs/flake.lock=. 应用依赖可相对独立地维护和更新; 根 flake 仍决定模块启用, 公共 overlay 接入和最终系统构建. 更新子项目 inputs 后应同步根 lock graph. 单独使用子 flake 时, 本地 lockfile 不纳入版本控制; 没有本地 lockfile 时, 子 flake 不提供独立的已提交锁定基线.

子项目 inputs 包括:
- =personal-nixpkgs=: 提供 =mkFlake= 和通用 package library, 其 =nixpkgs= 跟随子项目输入; =flake-parts= 和 =treefmt-nix= 由该输入管理, 不再直接声明为子项目输入.
- =emarccs=: 提供 editor 的 Emacs overlay, 固定 revision, 其内部 =personal-nixpkgs= 依赖由自身锁定.
- =lem= 和 =nixvim=: 提供 editor 所需的 overlay 和 Home Manager module.
- =niri-flake=: 提供 Niri 的 OS overlay 和 Home Manager module.
- =sops-nix=: 提供 SOPS 的 NixOS 和 Home Manager modules.
- =git-agent-workflow=: 通过 =share= overlay 提供持久记忆工具.
- =lean4-nix=: 通过 =share= overlay 提供 =lean4= 二进制包.
- =zotero-fix-nixpkgs=: 固定 nixpkgs revision, 通过 =share= overlay 提供对应 =zotero= 包.

=emarccs= 的 =flake-parts= 和 =treefmt-nix= 分别跟随子项目 =personal-nixpkgs= 的对应输入; =lem=, =nixvim=, =git-agent-workflow= 和 =lean4-nix= 的 =flake-parts= 也跟随 =personal-nixpkgs/flake-parts=.

=pkgs/flake.nix= 仅选取 =personal-nixpkgs.lib.packages=, 与 [[file:./pkgs/lib/default.nix][pkgs/lib/default.nix]] 的本地扩展通过 =mergeAttrsRecursive { allowOverrides = false; }= 合并为子项目的 =llib=, 禁止覆盖同名定义. 通用 =llib.packages= 由外部库提供; 本地扩展提供共享值类型, 子项目 =llib= 与根 =llib= 分开. [[file:./pkgs/pkgs/default.nix][pkgs/pkgs/default.nix]] 使用它生成 overlays 和 OS/HM 模块入口. =package.nix= 定义独立包, =overlay.nix= 注入包或命名空间; 对已有包的纯定制直接写在 =overlay.nix= 中; =os/default.nix= 和 =hm/default.nix= 提供包附带的模块. =mkOverlays= 通过 =groups= 生成本地 overlay 分组: =legacy= 包含全部本地扩展并通过 =export = true;= 提供扩展后 package set 的 =pkgs.legacyPackages=, =share= 排除 =rage-armored=. 各组通过 =exclude= 选择扩展, 可共享同一包定义.

包与测试的 overlay 源文件使用带参数的构造函数, 返回标准的双参数 overlay. 无构造参数时写作:

#+begin_src nix
{ }: final_: prev_: {
  example = final_.callPackage ./package.nix { };
}
#+end_src

外层构造参数与内层 =final_= / =prev_= 分开, =mkOverlays= 返回的仍是可供 Nixpkgs 使用的标准 overlays. =texlivePackages= 的聚合由外部 package library 内置规则处理, 本地只保留 =luadraw= 等包的定义.

子 flake 当前提供以下集成入口:
- =overlays.legacy=: 包含全部本地包扩展, 并提供按 =overlayFile = "overlay.nix"= 发现的 =pkgs.legacyPackages= 命名空间.
- =overlays.share=: 本地包扩展中排除 =rage-armored=, 并加入 GAW, Lean 和 Zotero 的集成.
- =overlays.editor=: 组合 emarccs 和 Lem 的 overlays, 并为 Lem 补充依赖及桌面入口.
- =nixosModules.share= 和 =homeModules.share=: 汇集包附带的 OS/HM 模块.
- =nixosModules.<name>= 和 =homeModules.<name>=: 显式导出 Feature 原生模块及其同作用域依赖, 不再按目录自动生成 exports.
- =nixosModules.editor= 和 =nixosModules.niri=: 分别在原生 Feature 启用时向系统 package set 提供 Editor 和 Niri overlays. 保留 =home-manager.useGlobalPkgs = true=.
- =homeModules.editor= 和 =homeModules.niri=: 分别组合上游 Nixvim、Niri 与本地 HM 模块.
- =nixosModules.sops= 和 =homeModules.sops=: 分别组合 sops-nix 的 OS/HM 模块与本地 SOPS 模块. Agenix 和 Agenix-rekey 仍由 root 提供.

=pkgs/pkgs/= 组织软件包和随包提供的 integrations. =pkgs/modules/= 组织独立功能, 采用 =modules/<name>/{fp,os,hm}= 的功能优先布局. 本阶段提供 =os/= 和 =hm/=, 由子 flake 显式组合 Feature 专用上游原生模块.

根 flake 通过 =perSystem.nixpkgs.overlays= 接入 =inputs.local-nixpkgs.overlays.legacy=, 使用 =mkFlake= 提供的 =pkgs= 并导出 =legacyPackages = pkgs.legacyPackages;=. checks, devShells 和 rekey 工具共同使用该 =pkgs=; =agenix-rekey.agePackage= 直接取 =pkgs.rage-armored=.

根 flake 通过 =moduleRegistry.share= 接入公共 overlays/modules, 通过 =moduleRegistry.features= 选择 Feature module exports 并提供过渡配置映射. Feature 专用 overlays 由相应 OS export 在启用时提供.

本地 package 包括:
- =codex=: 为 Codex wrapper 补充 Python/PyYAML 运行环境.
- =difftastic=: 应用 Haskell parser 修复.
- =git-maintenance=: 安装仓库维护 skill.
- =pi-coding-agent=: 为 Pi 设置离线运行环境.
- =piPackages=: 提供 agentic search, context, web search 和 workspace history 扩展, 以及相应依赖处理和安装检查文件.
- =rage-armored=: 基于 =pkgs.rage= 安装 wrapper, 将原始二进制保留为 =rage-unwrapped=, 并在常规加密调用中默认注入 =--armor=; 同时用作 =agenix-rekey.agePackage=.
- =texlivePackages=: 扩展 TeX Live 包集合, 包括 =luadraw=.
- =wayfile=: 提供 Wayfile 包和 Home Manager module.

[[file:./modules/hosts/boot-manager.nix][modules/hosts/boot-manager.nix]], [[file:./modules/hosts/identity.nix][modules/hosts/identity.nix]], [[file:./modules/hosts/shared.nix][modules/hosts/shared.nix]] 和 [[file:./modules/hosts/wireguard.nix][modules/hosts/wireguard.nix]] 分别消费 host metadata, 生成 boot manager, identity, shared capability 和 WireGuard topology/secret 的配置.

[[file:./modules/hosts/ssh-targets.nix][modules/hosts/ssh-targets.nix]] 从 =networking.wireguard.topology= 与 Host Registry 生成系统级 SSH 客户端别名 =<hub>.<node>=, 使用拓扑中的 IPv4 地址作为 =HostName=. 同一节点经不同 Hub 访问时共用 =HostKeyAlias= 与 Registry 中的 SSH host public key, 并由 =programs.ssh.knownHosts= 声明式验证服务器身份. =programs.ssh.hosts= 的 =order= 从 1000 开始, 依据 =(hub.number, node.number)= 排序分配. 当选中 Host 没有 WireGuard 配置时不生成这些条目; 参与生成的节点缺少 SSH host public key 时显式报错. 该集成不依赖 =modules/users/=, 不指定 SSH 登录用户、认证凭据或认证方法, 也不启用或修改 SSH 服务端. 别名只描述网络路径与服务器身份, 不保证 SSH 登录权限.

各 host 的 =_metadata.fp.nix= 由 registry 的 metadata 子模块加载, 用于声明 UID registry, monitor, public IP, WireGuard 和 identity metadata. =ssh.private.age= 与 =wireguard.private.age= 分别保存该 host 的加密 SSH host private key 与 WireGuard private key, 并由 =_metadata.fp.nix= 引用.

=identity.nix= 将当前 host 的非空 SSH 私钥备份引用登记为 =age.secrets.ssh-identity=, 设置 =intermediary = true;=, 使其参与 =agenix edit=, =agenix view= 和 =agenix update-masterkeys=. host rekey 跳过该备份, 上游 agenix module 安装 dummy secret, SSH host 私钥的安装与恢复需单独处理. 备份登记独立于 =identity.rootAccess=; 后者只控制 YubiKey 工具和 =pcscd= 的启用.

* 测试
[[file:./tests/default.nix][tests/default.nix]] 调用 =llib.tests.mkChecks=, 按 =test-overlay.nix= 发现各组测试入口, 在独立测试 scope 中组合定义并收集检查派生物. 嵌套 check 名称以 =-= 连接. 测试覆盖 FP validator 发现/组合/惰性边界, 自定义类型, Registry 的 =existModule= 派生与只读约束, host 相关函数与配置适配器. 子 flake 持有原生 Feature enable 契约和 SOPS helper 检查, 根 flake 使用同一锁图转发这两项. Host 函数测试还覆盖 WireGuard SSH targets 的多 Hub 别名、排序、主机身份去重、缺失公钥以及不依赖用户模块的系统级集成.

各组测试的 =test-overlay.nix= 使用与包相同的外层构造协议, 通过 =final.callPackage ./test.nix= 调用测试体. =test.nix= 保存断言和检查派生物, fixtures 保留在所属组内; 专用入口文件名避免将 fixtures 误识别为测试组.

根 flake 向测试总入口传入 =lib=, =pkgs=, =llib= 和 =modules = ./modules;=. 总入口通过 =mkChecks.args= 注入 =lib=, =modules=, 从 =pkgs= 提取的 =runCommand= 及选定库命名空间, 不向各组测试传递整套 =pkgs= 或 =llib=. 库依赖展平为 =llibFlakeParts=, =llibModules= 等小驼峰名称, 含 =-= 的名称也按词转换, 各组 overlay 再显式映射为 =flakeParts=, =moduleLib= 等普通参数名, 保留测试体中的 =namespace.member= 调用形式. =mkChecks.args= 用于测试 scope 和 =callPackage= 注入, 不属于 overlay 外层构造参数.

测试对所在目录之外的依赖通过函数参数传入, 禁止使用 =../*= 或 =../../*= 等父目录相对路径直接取得依赖. 需要真实模块树的测试通过 =modules= 参数接收该目录, 不依赖仓库根路径.

检查集合通过根 =perSystem.checks= 导出. 根 flake 使用 =treefmt.flakeCheck = true;= 接入格式检查, 本地不再逐项声明 formatter 程序. 本地 =treefmt.settings.excludes= 排除 =*.patch=, =.gitignore=, =LICENSE=, =README.org=, =flake.lock= 和 =*.age=.
