#+TITLE: NixOS Configuration
#+AUTHOR: aRenCoco

* 简介
这是一个基于 Flake 的 NixOS 配置仓库.

* 架构约定
=flake.nix= 是最终组装层, 通过 =personal-nixpkgs.lib.mkFlake= 组织统一的 flake-parts (FP) option space, 声明每台系统的选择, 接入外部 flake inputs. 本地 FP modules 由 =modules/default.nix= 逐层显式组合并登记对象. =pkgs/= 是独立的 package 子项目, 管理应用及 Feature 专用 inputs, 包定义和原生模块输出. 根 =flake.lock= 记录系统消费的依赖版本.

- =modules/hosts/<name>/default.nix= 和 =modules/users/<name>/default.nix= 是顶层 FP modules, 分别贡献 Host/User Registry 中的领域数据及 =module= option. =os/= 和 =hm/= 则是对应原生 module system 的入口. Host 管理主机资源和 UID registry, User profile 描述个人环境, Account 在具体 System configuration 中绑定 UID 与登录身份.
- Feature implementations 位于 =modules/features/=, 由各 Feature 的 FP 入口显式登记. OS 和 HM 各自选择. Root =flake.nix= 将子 flake 提供的外部 modules 和 overlays 接入相应 Feature. Workloads 由 =modules/workloads/= 登记, 由具体系统选择并配置.
- =baseModule= 提供始终导入的原生基础配置, 包括 =modules/base/= 中的本地基础模块和主机公共接线. Home Manager 是明确的构造参数, 其公共 HM modules 通过 =home-manager.sharedModules= 接入.

* Option 和组装协议
** FP 项目配置
FP options 全局可访问, 不将整个 FP configuration 复制到原生 NixOS/HM option space. Host 和 User 各有 typed FP submodule schema, 不再使用统一 descriptor 或 metadata namespace. =module= 是普通的 =deferredModule= option, 与其他领域数据平级. 通过 =modules/default.nix= 及各级目录入口逐层显式引入各对象定义与 schema 扩展; 不按目录发现模块、声明或 validators.

#+begin_src nix
nixosBuilderArgs = {
  nixosSystem = ...;
  homeManager = ...;
  baseModule = ...;
  specialArgs = ...;
  hostRegistry.thinkbook = {
    number = 2;
    # ... Host data ...
    module = ...;
  };
  userRegistry.lingyu = {
    features.sops.module = { ... };
    module = ...;
  };
  featureRegistry = {
    os = { ... };
    hm = { ... };
  };
  workloadRegistry = { ... };
};
#+end_src

=nixosBuilderArgs.hostTopology= 是由 Host Registry 派生的只读 FP option, 保留既有 WireGuard topology 的结构与地址分配规则. Registry entry 的只读 =name= 由其 key 派生, 供直接选择时标识 Registry 对象. =host= 和 =profile= 以输入值的 =name= 在对应 Registry 中重新解析最终对象, 不合并不同选择. 通常直接引用相应 Registry entry; 输入中的其他字段不会覆盖 Registry 数据.

#+begin_src nix
nixosConfigurations.nixos = {
  host = config.nixosBuilderArgs.hostRegistry.thinkbook;
  features.shell.enable = true;
  features.editor.enable = true;
  users."1000" = {
    username = "lingyu";
    profile = config.nixosBuilderArgs.userRegistry.lingyu;
    features.shell.enable = true;
    features.editor = {
      enable = true;
      module = { pkgs, ... }: {
        features.editor.emacs = {
          enable = true;
          programs.package = pkgs.emacs-pgtk;
        };
      };
    };
  };
  workloads.wbo = {
    enable = true;
    module.workloads.wbo = {
      ip = config.nixosBuilderArgs.hostTopology.aliyun.nodes.thinkbook;
      port = 18000;
      networkInterface = config.nixosBuilderArgs.hostTopology.aliyun.name;
      allowedSourceIp = config.nixosBuilderArgs.hostTopology.aliyun.nodes.aliyun;
    };
  };
};
#+end_src

Account entry 的存在即表示构造该账户, 不再提供 Account enable. UID key 必须是 canonical decimal, 不小于 1000, 且已由 Host 注册; 用户名在每个系统内唯一, homeDirectory 默认 =/home/${username}= 且必须为绝对路径. Host 仍可注册未被 Account 使用的 UID.

** 原生模块组合
系统平台由选中的 Host module 通过原生 =nixpkgs.hostPlatform= 声明. 构造器以 =system = null;= 调用 =nixosSystem=, FP System configuration 不重复声明平台.

=llib.flakeParts.mkNixosConfigurations= 接收 =builderArgs= 和 =configurations=, 生成最终 =flake.nixosConfigurations=. 构造器导入 Home Manager、baseModule 和选中的 Host module, 再按 System configuration 导入 OS Features、Workloads 与每个 Account 的 HM profile 和 Features. Account 同时贡献 NixOS 与 HM 的身份字段, 两侧以 UID 字符串为 key. Home Manager 继续使用全局 package set (=useGlobalPkgs = true=).

每个已登记 Feature/Workload 具有默认 =false= 的 FP =enable= 及 =module= option. 启用时依次导入 Registry implementation、合并后的 consumer module 和显式原生 enable contribution; 禁用时两类 deferredModules 都不加载, 不贡献原生 enable. OS/HM implementations 各自声明原生 =features.<name>=, Workloads 声明原生 =workloads.<name>=. Feature 不启用、导入或配置其他 Feature, 可读取其他 Feature 的已定义值并通过原生 assertions 检查实际依赖. 外部 flake inputs 仅在所属 flake.nix 中引用. 选中对象的 native imports 在 FP 层决定, 不依赖同一原生求值的 =config= 计算 imports.

** 接线与验证
构造器仅传递所需项目数据: NixOS 获得 =host=、不含 deferredModule 的 =hostRegistry= 及 =hostTopology=, OS/HM 均获得公共 =specialArgs=. NixOS 仍通过 =networking.wireguard.topology= 暴露拓扑. 不再使用旧 configuration adapter 或镜像 option space. 特定 Feature 的接线不属于构造器.

FP modules 可以扩展 Registry 与 System/Account 的 submodule schema. Greeter 和 Niri 的 FP 入口各自将选中 Host 的完整默认 Monitor 和 monitors 数据接入相应 native Feature; SOPS 的 FP 入口从 Account 的 HM SOPS 选择派生 OS SOPS 的授权 UID. 接线结果均进入对应 System 或 Account 的 =features.<name>.module=, 不由构造器处理业务逻辑.

User Registry 的 =features.<name>.module= 是稀疏的只读 =llib.types.deferredModuleFragment= option, 与通用 =module= (完整 HM deferredModule) 区分. 它接受 attrset 或函数, 不负责选择或启用 Feature. 通用 FP schema 通过 =mkFeatureModule= 将该值封装成原生 module 并合并到引用此 User 的 Account 对应 Feature 的 deferredModule. 该函数使用 =llib.modules.mapModule= 保留函数的参数需求并映射其返回值, 仅在 Account 选择对应 Feature 后于其 HM scope 求值. 返回值直接定义 =features.<name>= 下的配置, 不声明新的原生 options 或 imports, 也不在 FP 层重复声明业务数据类型.

#+begin_src nix
nixosBuilderArgs.userRegistry.lingyu.features = {
  sops.module = {
    defaultSopsFormat = "yaml";
    defaultSopsFile = ./sops/default.yaml;
    secretsInput = [ ... ];
  };
  agent.module = { config, lib, ... }: {
    pi.providers = lib.mkIf (config.features.sops.enable or false) {
      deepseek = {
        enable = true;
        apiKeyFile = config.sops.secrets."deepseek.apiKey.pi".path;
      };
    };
  };
};
#+end_src

内部数据接线与派生接口通常为 =readOnly=, 不通过多个生产者合并数据; 可选输入按其 native option 类型和消费契约处理. SOPS HM 可不声明 secrets, 但启用时要求 OS SOPS 启用并消费其只读 =features.sops.ageKeys.hm.path=; Agent 独立消费 provider 的 enable 和 =apiKeyFile=, 不依赖 SOPS. 原生接线读取实际 OS/HM config, 例如 Greeter 消费 Niri/X11 session packages (Niri 优先), HM Shell 消费 OS =features.shell.{bash,zsh}.package=, File-manager 消费 OS file chooser 和当前 HM Niri 选择. OS Noctalia、OS FileChooser 默认随所属 Feature 启用, HM Noctalia 默认读取 OS Niri/Noctalia 状态, HM Waybar 默认随 HM Niri 启用且 HM Noctalia 禁用.

Host 数据不变量由 =modules/hosts/options.nix= 的 option types 与 =apply= 表达: Registry 保证 number 全局唯一, monitors 保证名称唯一、默认 monitor 至多一个且具有 mode, users 保证 UID registry key 与值一致, wireguard 保证 endpoint 非空时 listenPort 非空. =apply= 在对应 option 被消费时执行; =checks.host-registry= 强制求值所有 Host 的这些领域数据, 包括未被选中的 Host, 而不求值 deferredModules. Registry 的 number 检查不应依赖再次读取同一 Registry 的最终值; 局部字段可以读取其他已登记对象. Greeter 接线自行要求唯一默认 monitor, HM Niri 使用原生 assertion, OS Niri 不需要显示器数据. 构造时验证所有 System configurations 的选择及 Account 绑定, 不强制未选中的 deferredModules. 仅依赖最终原生状态的约束由相应原生 assertions 检查 (例如 Proxy 互斥、Noctalia 服务依赖、HM SOPS 与 API keys).

仓库根目录放置系统 flake 入口, lock 文件, README, package 子项目和模块目录. 根 =flake.nix= 使用 =personal-nixpkgs.lib.mkFlake inputs.nixpkgs= 组织输出, 包括 =nixosConfigurations=, =legacyPackages=, =checks=, =devShells= 和 =formatter=; overlays 和包附带的 OS/HM 模块由 =pkgs/flake.nix= 导出. 根 =nixpkgs= 使用 =nixos-unstable=, 并启用 =nix-command= 与 =flakes=.

根 flake 和 package 子项目均向 =mkFlake= 传入接收 =lib= 的配置回调, 并声明 =moduleLocation = __curPos.file;=. 根回调提供 =llib= 和 =specialArgs.rootPath=, 子项目回调提供自己的 =llib= 与 =lpkgs=.

根 flake inputs 按使用位置集中传递:
- =nixpkgs=: 提供最终系统与 =perSystem= 的 package set, 也是多个 inputs 的 =follows= 目标.
- =personal-nixpkgs=: 提供 =mkFlake= 组装入口与 =llib.tests= 测试组织接口, 其 =nixpkgs= 跟随根输入; 与 package 子项目中的同名输入在根 lock graph 中分别记录版本. =flake-parts= 和 =treefmt-nix= 由该输入管理, 不再直接声明为根输入.
- =local-nixpkgs=: 通过 =path:./pkgs= 引用 package 子项目, 将其公共 overlays/modules 接入 baseModule, 将 Feature 所需的外部 modules 和 overlays 接入相应 Registry entry; =legacy= overlay 用于构造根 =perSystem= 的 package set 和 =legacyPackages= 输出.
- =home-manager=: 通过 =nixosBuilderArgs.homeManager= 导入每台系统.
- =agenix= 和 =agenix-rekey=: 提供 age secret 与 rekey module; =agenix-rekey.agePackage= 使用本仓库的 =rage-armored=, =agenix-rekey= 的 =treefmt-nix= 跟随 =personal-nixpkgs/treefmt-nix=.
- =nix-flatpak=: 注入 thinkbook host 的 Flatpak module.
- =nixvirt=: 注入 thinkbook host 的 NixVirt module.
- =nixos-wsl=: 注入 wsl host 的 NixOS-WSL module.
- =nixos-anywhere= 和 =disko=: 提供部署 devShell 与 aliyun host 的 disko module; =disko= 通过 =follows= 复用 =nixos-anywhere/disko=, =nixos-anywhere= 的 =treefmt-nix= 跟随 =personal-nixpkgs/treefmt-nix=.

[[file:./lib/default.nix][lib/default.nix]] 导出 =llib.hosts=, =llib.flakeParts=, =llib.modules= 与 =llib.types=. =hosts.nix= 提供 WireGuard network data、拓扑、接口/firewall 及 SSH targets 的派生; =mkWireGuardTopology= 返回全局 topology, =mkWireGuardNetworks= 直接返回指定 Host 的原生 networking 配置; =flakeParts.nix= 声明通用 FP schema 并构造原生系统和 Account modules. =modules.nix= 提供 =mapModule=, 在保留 callable value 的原生参数声明的同时变换其返回值, 不预设 module 的结构或目标 namespace. =types.nix= 中的 =deferredModuleFragment= 接受 attrset 或 callable value, 在合并时将普通 attrset 规范化为常值函数; 它不负责完整 module 的组合或 namespace 限制. 共享值类型由 =types.nix= 与 =monitor-type.nix= 定义, FP 与原生模块通过 =llib.types= 使用同一组类型. 根 flake 从 personal-nixpkgs 引入 tests. Host domain schema 和项目特有接线由显式 FP modules 扩展, 不在构造器内硬编码 Feature 业务逻辑.

[[file:./pkgs/flake.nix][pkgs/flake.nix]] 独立使用时由自身 inputs 声明应用依赖, =nixpkgs= 指向 =nixpkgs-unstable=. 根 flake 将 =local-nixpkgs= 的 =nixpkgs= 与 =personal-nixpkgs= 分别指向根输入, 并通过根 [[file:./flake.lock][flake.lock]] 记录其依赖版本, 仓库不跟踪 =pkgs/flake.lock=. 应用依赖可相对独立地维护和更新; 根 flake 仍决定模块启用, 公共 overlay 接入和最终系统构建. 更新子项目 inputs 后应同步根 lock graph. 单独使用子 flake 时, 本地 lockfile 不纳入版本控制; 没有本地 lockfile 时, 子 flake 不提供独立的已提交锁定基线.

子项目 inputs 包括:
- =personal-nixpkgs=: 提供 =mkFlake= 和通用 package library, 其 =nixpkgs= 跟随子项目输入; =flake-parts= 和 =treefmt-nix= 由该输入管理, 不再直接声明为子项目输入.
- =emarccs=: 提供 editor 的 Emacs overlay, 固定 revision, 其内部 =personal-nixpkgs= 依赖由自身锁定.
- =lem= 和 =nixvim=: 提供 editor 所需的 overlay 和 Home Manager module.
- =niri-flake=: 提供 Niri 的 OS overlay 和 Home Manager module.
- =sops-nix=: 提供 SOPS 的 NixOS 和 Home Manager modules.
- =git-agent-workflow=: 通过 =share= overlay 提供持久记忆工具.
- =lean4-nix=: 通过 =share= overlay 提供 =lean4= 二进制包.
- =zotero-fix-nixpkgs=: 固定 nixpkgs revision, 通过 =share= overlay 提供对应 =zotero= 包.

=emarccs= 的 =flake-parts= 和 =treefmt-nix= 分别跟随子项目 =personal-nixpkgs= 的对应输入; =lem=, =nixvim=, =git-agent-workflow= 和 =lean4-nix= 的 =flake-parts= 也跟随 =personal-nixpkgs/flake-parts=.

子项目的 =llib= 仅包含外部库提供的 =personal-nixpkgs.lib.packages=, 与根 =llib= 分开. [[file:./pkgs/pkgs/default.nix][pkgs/pkgs/default.nix]] 使用它生成 overlays 和 OS/HM 模块入口. =package.nix= 定义独立包, =overlay.nix= 注入包或命名空间; 对已有包的纯定制直接写在 =overlay.nix= 中; =os/default.nix= 和 =hm/default.nix= 提供包附带的模块. =mkOverlays= 通过 =groups= 生成本地 overlay 分组: =legacy= 包含全部本地扩展并通过 =export = true;= 提供扩展后 package set 的 =pkgs.legacyPackages=, =share= 排除 =rage-armored=. 各组通过 =exclude= 选择扩展, 可共享同一包定义.

包与测试的 overlay 源文件使用带参数的构造函数, 返回标准的双参数 overlay. 无构造参数时写作:

#+begin_src nix
{ }: final_: prev_: {
  example = final_.callPackage ./package.nix { };
}
#+end_src

外层构造参数与内层 =final_= / =prev_= 分开, =mkOverlays= 返回的仍是可供 Nixpkgs 使用的标准 overlays. =texlivePackages= 的聚合由外部 package library 内置规则处理, 本地只保留 =luadraw= 等包的定义.

子 flake 当前提供以下集成入口:
- =overlays.legacy=: 包含全部本地包扩展, 并提供按 =overlayFile = "overlay.nix"= 发现的 =pkgs.legacyPackages= 命名空间.
- =overlays.share=: 本地包扩展中排除 =rage-armored=, 并加入 GAW, Lean 和 Zotero 的集成.
- =overlays.editor=: 组合 emarccs 和 Lem 的 overlays, 并为 Lem 补充依赖及桌面入口.
- =nixosModules.share= 和 =homeModules.share=: 汇集包附带的 OS/HM 模块.
- =overlays.niri=: 转发 niri-flake 的 overlay.
- =homeModules.nixvim= 和 =homeModules.niri=: 分别转发上游 Nixvim 与 Niri HM modules.
- =nixosModules.sops= 和 =homeModules.sops=: 转发 sops-nix 的 OS/HM modules. Agenix 和 Agenix-rekey 仍由 root 提供.

=pkgs/pkgs/= 组织软件包和随包提供的 integrations. Nixvim、Niri 与 SOPS 的 inputs 暂时保留在子 flake, 其 exports 不再组合本地 Feature implementations.

根 flake 通过 =perSystem.nixpkgs.overlays= 接入 =inputs.local-nixpkgs.overlays.legacy=, 使用 =mkFlake= 提供的 =pkgs= 并导出 =legacyPackages = pkgs.legacyPackages;=. checks, devShells 和 rekey 工具共同使用该 =pkgs=; =agenix-rekey.agePackage= 直接取 =pkgs.rage-armored=.

根 flake 通过 =baseModule= 接入公共 overlays/modules. Feature 的外部依赖通过对应的 =featureRegistry.{os,hm}= 条目与本地 deferredModule 合并, Editor 和 Niri 的专用 overlays 仍在原生 OS Feature 启用时贡献给系统 package set.

本地 package 包括:
- =codex=: 为 Codex wrapper 补充 Python/PyYAML 运行环境.
- =difftastic=: 应用 Haskell parser 修复.
- =git-maintenance=: 安装仓库维护 skill.
- =pi-coding-agent=: 为 Pi 设置离线运行环境.
- =piPackages=: 提供 agentic search, context, web search 和 workspace history 扩展, 以及相应依赖处理和安装检查文件.
- =rage-armored=: 基于 =pkgs.rage= 安装 wrapper, 将原始二进制保留为 =rage-unwrapped=, 并在常规加密调用中默认注入 =--armor=; 同时用作 =agenix-rekey.agePackage=.
- =texlivePackages=: 扩展 TeX Live 包集合, 包括 =luadraw=.
- =wayfile=: 提供 Wayfile 包和 Home Manager module.

=default.nix= 是 FP 入口, 向 =nixosBuilderArgs.baseModule= 贡献本地 OS/HM modules; =os/default.nix= 组合其余公共原生 OS modules.

=os/default.nix= 提供 Nix, 防火墙, 基础工具, age 与 Home Manager 公共配置, 并声明原生 =xdg.createUserDirectories= (默认 false); =hm/default.nix= 提供 Fastfetch, XDG 路径和 home state version. Host module 直接使用 =nixpkgs.config.allowUnfreePackages= 与 =xdg.createUserDirectories= 声明本机策略. 两侧基础模块由 =baseModule= 无条件接入, 不参与 Feature selection. Host 通过其原生 =module= 显式定义 =base.{bluetooth,bootManager,networkmanager,power}.enable=; 这些只读 native options 不设默认值, 控制对应 Base 配置贡献是否参与合并, 禁用时不强制关闭上游服务. 它们不再属于 Host Registry 的结构化 FP 数据.

=bluetooth.nix=, =boot-manager.nix=, =networkmanager.nix= 与 =power.nix= 分别声明并消费对应的 =base.*.enable=, 保留各自的原生配置贡献; boot manager 仍消费 Host monitor 数据派生分辨率. =identity.nix= 与 =wireguard.nix= 消费选中的 Host 领域数据, 生成 identity 与 WireGuard interface/secret 的配置; topology 由 FP 层派生并投影到原生 option.

[[file:./modules/base/os/ssh-targets.nix][modules/base/os/ssh-targets.nix]] 从 =networking.wireguard.topology= 与 Host Registry 生成系统级 SSH 客户端别名 =<hub>.<node>=, 使用拓扑中的 IPv4 地址作为 =HostName=. 同一节点经不同 Hub 访问时共用 =HostKeyAlias= 与 Registry 中的 SSH host public key, 并由 =programs.ssh.knownHosts= 声明式验证服务器身份. =programs.ssh.hosts= 的 =order= 从 1000 开始, 依据 =(hub.number, node.number)= 排序分配. 当选中 Host 没有 WireGuard 配置时不生成这些条目; 参与生成的节点缺少 SSH host public key 时显式报错. 该集成不依赖 =modules/users/=, 不指定 SSH 登录用户、认证凭据或认证方法, 也不启用或修改 SSH 服务端. 别名只描述网络路径与服务器身份, 不保证 SSH 登录权限.

=identity.nix= 将当前 host 的非空 SSH 私钥备份引用登记为 =age.secrets.ssh-identity=, 设置 =intermediary = true;=, 使其参与 =agenix edit=, =agenix view= 和 =agenix update-masterkeys=. host rekey 跳过该备份, 上游 agenix module 安装 dummy secret, SSH host 私钥的安装与恢复需单独处理. 备份登记独立于 =identity.rootAccess=; 后者只控制 YubiKey 工具和 =pcscd= 的启用.

* 测试
[[file:./tests/default.nix][tests/default.nix]] 调用 =llib.tests.mkChecks=, 按 =test-overlay.nix= 发现各组测试入口, 在独立测试 scope 中组合定义并收集检查派生物. 嵌套 check 名称以 =-= 连接. 测试覆盖 FP schema 扩展与合并、禁用模块不导入、Account 的独立 HM 选择与静态绑定约束、自定义类型及 Host 相关函数. 原生 Feature enable 契约和 SOPS helper 检查分别位于 =tests/native-feature-enables/= 与 =tests/sops-functions/=, 通过根测试入口直接登记, 不再转发子 flake 的 checks. Host 函数测试还覆盖 WireGuard SSH targets 的多 Hub 别名、排序、主机身份去重、缺失公钥以及不依赖用户模块的系统级集成.

各组测试的 =test-overlay.nix= 使用与包相同的外层构造协议, 通过 =final.callPackage ./test.nix= 调用测试体. =test.nix= 保存断言和检查派生物, fixtures 保留在所属组内; 专用入口文件名避免将 fixtures 误识别为测试组.

根 flake 向测试总入口传入 =lib=, =pkgs=, =llib=, =modules = ./modules;= 和最终 =featureRegistry=. 总入口通过 =mkChecks.args= 注入 =lib=, =modules=, 从 =pkgs= 提取的 =runCommand= 及选定库命名空间, 不向各组测试传递整套 =pkgs= 或 =llib=. Native Feature 测试使用实际 Registry 中的原生实现, 对由 fixture 提供上游声明的部分直接使用本地实现; 通过 =featureTestPackages= 注入 Shell 测试实际消费的包, 并通过 =llibTypes= 注入共享值类型. 库依赖展平为 =llibFlakeParts=, =llibHosts= 等小驼峰名称, 含 =-= 的名称也按词转换, 各组 overlay 再显式映射为 =flakeParts=, =hosts= 等普通参数名, 保留测试体中的 =namespace.member= 调用形式. =mkChecks.args= 用于测试 scope 和 =callPackage= 注入, 不属于 overlay 外层构造参数.

测试对所在目录之外的依赖通过函数参数传入, 禁止使用 =../*= 或 =../../*= 等父目录相对路径直接取得依赖. 需要真实模块树的测试通过 =modules= 参数接收该目录, 不依赖仓库根路径.

检查集合通过根 =perSystem.checks= 导出. Host FP module 另外贡献 =host-registry=, 强制全部已登记 Host 的受约束数据, 不导入未选中实现. 根 flake 使用 =treefmt.flakeCheck = true;= 接入格式检查, 本地不再逐项声明 formatter 程序. 本地 =treefmt.settings.excludes= 排除 =*.patch=, =.gitignore=, =LICENSE=, =README.org=, =flake.lock= 和 =*.age=.
